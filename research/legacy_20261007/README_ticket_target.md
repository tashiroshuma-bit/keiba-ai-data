# 馬券的中を目的とする計算 v1（2026-10-07）

このパッケージは、従来の「一番上の馬が勝ったか」を評価する処理とは独立して、**提示した馬券の的中**を評価する。標準 Python だけで動き、Google Colab を使わない。予算枠と実投票額を区別する。

## 変えた算出単位

1. 各券の事象を定義する。単勝＝1着、複勝＝8頭以上で3着以内・5〜7頭で2着以内、馬連＝1・2着を順不同、ワイド＝両馬3着以内、三連複＝指定3頭が3着以内。対象は5頭以上の全馬出走・同着なしの平地競走。4頭以下は明示的に停止。発売開始後の取消で払戻条件が変わらない場合もあるため、出走取消・返還は未対応として停止する。
2. 的中確率は **1〜3着の同時分布** から集計する。例えばワイドA-Bは全順序付き結果のうち両馬が上位3着にいる確率の合計。馬Aの勝ちスコアと馬Bの勝ちスコアを掛けない。異なる券が同時に当たり得るため、「どれか1券の的中確率」は各券の確率の和でもない。
3. 購入案を1レース単位で同じ結果に当てる。各結果の払戻下限 `Σ 的中券の(投票額÷100×オッズ由来の100円払戻下限)` を計算し、(a) 1券以上的中、(b) 総払戻が**実投票額以上**、(c) 払戻期待値、(d) 最悪時全額損失を別指標として記録。見送り額を投票額に入れない。
4. レース後はJRA確定の100円払戻を利用する。推奨と実購入の記録を混ぜない。予算5,000円と実投票2,500円なら損益・回収率の分母は2,500円。

## 実行

```bash
python3 -m unittest -v test_ticket_math.py
python3 ticket_math.py settle --plan examples/kyoto_20261004_plan.json --result examples/kyoto_20261004_result.json
python3 ticket_math.py settle --plan examples/tokyo_20261004_plan.json --result examples/tokyo_20261004_result.json
python3 ticket_math.py forecast --plan FUTURE_plan.json --scenarios FUTURE_joint_top3.json
python3 audit_ticket_baseline.py --legacy-predictions graded_identity_model_predictions.csv
```

2026年10月4日の事前固定10券を結果で照合すると、京都・東京とも推奨5,000円、払戻0円、計10,000円の仮想投票で0円。各レースの全券に⑱または⑯が入るため、`single_horse_exposure_yen` は軸馬に5,000円と出る。この例は結果検算であり、予想性能の改善証明ではない。

## 入力

- `plan.json`: `race_id`, `field`（全出走馬番）、`budget_yen`, `scheduled_start` と `locked_at`（タイムゾーン必須）、`tickets`。各券は `type` = `WIN`, `PLACE`, `QUINELLA`, `WIDE`, `TRIO`、`horses`、`stake_yen`。予測時には更に `odds_observed_at`, `odds_source_url`, 各券の `price_floor_per_100_yen` を必須とする。確認価格がロック時点の10分超前なら停止。100円単位で予算以内にする。
- `joint_top3.json`: `race_id`, `generated_at`, `validation_status: independently_validated`, `validation_report_id`, `top3: [{"order": [1,2,3], "probability": 0.001}, ...]`。フィールドの **n(n−1)(n−2)** 通りを漏れなく列挙して合計1とする。検証IDは呼出者の申告であり、このプログラム自体は校正成績や改ざん防止を監査しない。
- `result.json`: `race_id`, `confirmed_at`, `result_status: final_all_started_no_dead_heat`, JRAの `source_url`, `top3`, `jra_payout_per_100_yen`。的中券のキーは `WIDE:1-2`, `QUINELLA:1-2` など。的中した券の公式払戻が欠けていれば停止する。取消・返還・同着・降着は今回未対応。

オッズの事前価格は確定払戻ではない。ワイドの範囲表示は**下限**を円/100円に換算して入れ、馬連などは同時刻の値を記録する。最低オッズを割った券はプランに入れず、見送り額として残す。

## 次の学習・購入判断のゲート

現在の既存木モデルは各馬の**勝ちスコア**しか出さず、独立校正された上位3頭の同時分布はまだない。このため `forecast` の正当な実行材料がなく、現段階では券ごとの的中率・期待値や新しい買い目を数字で推奨しない。自己申告フラグを付けた架空分布は性能の証明にならない。

1. 2023〜2025年の全重賞・非重賞履歴を発走前時点で切り、**レース単位**で順序付き上位3頭を学習する。騎手・馬のID、脚質・頭数・枠・斤量・馬場、同型馬の数を発走時点に観測できた値に限る。2026年10月の結果を学習と独立検証の両方には使わない。
2. 2025年までで特徴量・校正法・馬券選択規則を固定し、未使用期間を時系列で評価する。モデルの上位3同時分布の対数損失、馬券種別の信頼度図とBrier、単純な同時刻市場オッズ基準と比較する。相関した券の成績はレース単位で集計する。今まで見た2026年7〜10月の結果は独立した将来評価と称さない。
3. 同じ全対象レース・同じ時刻の価格・1レース5,000円枠で旧案と新案を比較する。全レースで「購入したか／見送ったか」「1券以上的中率」「投票額回収率」「払戻期待値」「実現回収率・最大資金減少」を併記する。80%を狙うなら、低配当券を広く買って的中だけ増やした値ではなく、**投票額を回収したレースの割合と対象レースの購入率**をセットで評価する。
4. 校正済み同時分布と同時刻オッズの両方がそろった時のみ購入候補を探索する。発走前に固定した条件として、期待払戻下限が投票額を超える候補だけを残し、その中で投票額回収確率を最大化。軸馬1頭に全点を結ぶ案と分散案を開発期間で比較し、優位がなければ見送る。閾値や券数を結果後に変えない。

旧木モデルの数値を単勝勝率として校正し、さらに独立仮定でワイド確率へ換算する処理は入れていない。現在の成果は**計算・照合方法の実装**であり、新しい的中率の実測向上ではない。

## 既存28重賞の探索的な馬券事象基準

既存の `graded_identity_model_predictions.csv` の各レースで、スコア上位の馬番を事前に選ぶ単純規則を固定して数えた。今回パッケージの `graded_identity_model_predictions.csv` は参照用の元データで、7〜9月の結果は既にモデル設計時に閲覧済み。独立検証でも新モデルの改善実績でもない。

| 28レースでの固定規則 | 的中 | 必要点数/レース |
|---|---:|---:|
| 1位馬の単勝 | 5/28 | 1 |
| 1位馬の複勝 | 13/28 | 1 |
| 1位・2位のワイド | 4/28 | 1 |
| 上位3頭のワイド3点のどれか | 9/28 | 3 |
| 上位3頭の三連複 | 1/28 | 1 |

複勝やワイドの的中率だけを増やしても、馬券代を回収した割合・回収率が上がったとは言えない。過去のワイド・複勝・三連複の**発走前の同時刻オッズと公式払戻**を収集できるまで、資金配分の優劣と期待値は空欄とする。
