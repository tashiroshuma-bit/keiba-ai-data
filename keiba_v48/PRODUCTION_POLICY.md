# 結果オッズ基準と確率予測の試験本番採用

2026-10-19時点。発走前オッズの継続取得を前提とせず、結果の確定単勝オッズを市場比較・期待値順位の判断軸とする。確率予測を先に固定し、レース後に `result_odds.py` で `予測勝率 × 結果オッズ` を評価する。当該レースの結果オッズ・着順・払戻は予測モデルの入力にしない。

## 実データでの結果

2023年263レースで学習、2024年237レースで校正、2025年218レースで探索的検証。2025年は既に参照した期間であり、未見の最終テストではない。対象は公式ID・全頭構成・履歴等の条件を満たす選択標本。

| 指標 | 公表遅延2日を仮定 | 公表遅延7日を仮定 |
| --- | ---: | ---: |
| 確率1位の単勝的中率 | 26.6% | 26.1% |
| 確率1位に100円固定・回収率 | 78.6% | 77.8% |
| 結果オッズ市場基準の単勝的中率 | 34.4% | 34.4% |
| 最大期待値1頭・結果オッズによる事後参考回収率 | 112.4% | 105.9% |

事後参考回収率は `p × 結果オッズ >= 1.05` の最大1頭を100円で集計したもの。当時購入可能だったオッズや実運用収益を示さない。結果オッズ市場基準は確率モデルより的中率・対数損失とも良い。収益性の改善が確認済みという判定にはしていない。

## 未連携IDの原因と対応

公式根拠のある馬7,951頭・騎手161名。馬ID連携77,385行、騎手ID連携137,394行、両ID連携74,570行（従来60,768行）。

PDFと公式結果の同一レース・同一馬番を照合し、3レース以上で同じ正式名・IDに一致するPDF表記だけを別名辞書に採用した。採用は「島克駿→鮫島克駿」「島良太→鮫島良太」「幸英明ロ→幸英明」「.ルメール→C.ルメール」の4件。M.デムーロとC.デムーロが混在する「.デムーロ」は共通IDへ変換しない。

| 残件 | 行数 | 原因・扱い |
| --- | ---: | --- |
| 馬ID：照合可能な馬名・生年キーなし | 65,312 | 取得済み公式ページの範囲外等。根拠付きページを追加するまで保留 |
| 馬ID：生年不明 | 25 | 年齢・抽出を確認するまで保留 |
| 馬ID：PDF文字欠損 | 15 | 元資料との照合が必要 |
| 騎手ID：根拠コード未取得 | 1,935 | 取得範囲不足等。IDを補作しない |
| 騎手ID：公式結果に名前のみ・コードなし | 3,141 | 外国人騎手等。馬履歴は利用し、騎手履歴を中立評価 |
| 騎手ID：別名が曖昧・根拠不足 | 258 | 混同を防いで保留・中立評価 |
| 騎手ID：PDF文字欠損 | 9 | 保留・中立評価 |

不明騎手を共通の架空IDへ統合しない。馬IDは引き続き必須。騎手IDが不明なら `null` のまま騎手履歴から除外し、中立の縮約事前値を使う。検証対象には騎手ID不明101行を含む。

## 稼働入口

`deployment/active_manifest.json` と `active_model.json` を試験本番の有効モデルとして登録した。状態は `experimental_probability`。厳密な時点再現を検証済みとするフラグは false のまま。

```bash
python keiba_v48/live_predict.py predict \
  --db /path/to/jra_2023_2025.sqlite \
  --runners /path/to/current_complete_field.json \
  --manifest keiba_v48/deployment/active_manifest.json \
  --ledger /path/to/forward_ledger.sqlite \
  --output /path/to/prediction.json
```

出走馬入力は同一レースの全出走馬、公式馬ID、馬番、開催場、馬場種別、距離、タイムゾーン付き発走予定時刻、`features_asof`、出典URL、`field_complete=yes` が必要。騎手IDは不明なら null。入力例のキー・全頭検査は `strategy.validate_field` を参照。未来の観測時刻・締切経過・当該レースの結果ラベルは拒否する。

本番履歴はPDF取得・馬ID根拠・騎手ID根拠（既知の場合）の実観測時刻の最大値を使い、その時点より前の予測に混入させない。学習時の過去公表時刻には2日仮定を用いており、その制約を出力に残す。過去レースの確定単勝オッズは前走情報として表示するだけで、今回追加の学習特徴量にはしない。

出力は1～3着確率・フェア単勝オッズ・5%余裕の必要単勝オッズ。発走前オッズなしでも確率予測と台帳固定を行える。購入指示と投資額は空・0円。予測後に確定結果を取得して事後オッズ基準と比較する。今回の稼働確認は実アーカイブを使った架空将来レースの処理試験であり、実レースの予測実績ではない。常駐サービスや定期取得の配置は行っていない。

## 再現・監査

```bash
python keiba_v48/official_linkage.py --rebuild-from /path/to/verified_base.sqlite \
  --db /path/to/new_snapshot.sqlite --cache /path/to/jra-official-html \
  --report /path/to/linkage_audit.json
python keiba_v48/historical_replay.py --db /path/to/new_snapshot.sqlite \
  --output /path/to/replay --allow-missing-jockey
python -m unittest discover -s keiba_v48 -v
```

復元は検証済み原本を読み取り専用でメモリへ複製し、保存済み公式HTMLから再照合後、整合性検査済みの新規DBだけを公開する。途中の作業DB破損を検出したため、この経路で原本から作り直した。元DBは変更していない。完成DBの `integrity_check=ok`、外部キー違反0。正確な過去の結果公表時刻は未確認であり、架空の時刻で埋めない。

監査ファイルは `audits/production_linkage_2026_10_19.json`、`production_replay_lag{2,7}_2026_10_19.json`、`operational_smoke_2026_10_19.json`。評価レポートにはDB・コード・モデル・予測行のSHA-256を記録する。最終オッズ判定コードもハッシュ対象。公式資料は https://www.jra.go.jp/datafile/seiseki/ 。
