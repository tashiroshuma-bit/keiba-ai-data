## 今回のボトルネックと改善
v48まではPDF抽出候補JSONと独立出馬表JSONに記載されたSHA256が自己申告であり、**実際のローカル原本バイトとの照合が欠落**していた。

`jra_v49_byte_bound_e2e.py` を追加。ローカルの(1)開催場別PDFバイト、(2)独立出馬表の生バイト、(3)独立出馬表を構造化したJSONを同時に読み込み、双方のSHA256を計算。構造化JSON内のハッシュ・PDF URLとの一致を確認し、v47の実バイト解析とv48の12R候補照合を**単一の研究用コマンド**で接続する。

不一致、同一原本の二重利用、空ファイル、サイズ超過、非PDF、PDFパース失敗、馬番/馬名/斤量/時刻/頭数の不整合は拒否。出力JSONには原本バイトを含めず、計算ハッシュと検査結果のみ保存する。公式JRA原本をGitHubに保存しない。

**限界：** 生バイトを計算しても、その原本がJRAから取得された証拠、観測時刻、独立出馬表JSONへの転記の正しさ、取消、馬IDは認証できない。出力の `source_authenticity_proven`、`capture_time_authenticated`、`production_freeze_allowed`、`result_settlement_allowed`、`forward_prediction_fixed` は常にfalse。JSON候補の一致を本番の根拠にしない。

### 使用例（ローカルで原本が揃った後）
```bash
cd keiba_v48
python jra_v49_byte_bound_e2e.py \
  --program-pdf /private/jra_program.pdf \
  --independent-roster-raw /private/roster.html \
  --roster-json /private/roster.json \
  --program-url-claimed https://www.jra.go.jp/keiba/rpdf/pdf/20261025-04tokyo09.pdf \
  --observed-at-claimed 2026-10-29T09:00:00+09:00 \
  --out /private/v49_research.json
```
例の時刻は使い方を示す仮値であり、発走前の取得証拠ではない。入力原本は利用条件に従ってローカルに保持する。
