# 次回からの直前馬体重参照ルール（2026-10-31ユーザー指示）

全対象レースの最終確認で、馬体重・前走増減kg・前走比率、確認できる場合は同馬の過去3走の範囲と休養間隔を参照する。騎手の負担重量（斤量）と混同しない。初出走・計不・未発表を0kg増減で埋めない。

- 出馬表の当日発表値を出典URL・実観測時刻・原本または観測テキストのSHA256とともに保存。ハッシュの対象を明記し、観測テキストのハッシュをHTTP原本と呼ばない。
- 日付、馬番と馬名、実観測時刻が発走前であることを検査。結果画面・確定成績から取得した当日値を発走前観測に流用しない。
- 全頭が未確認でも基礎予測は出すが「馬体重未確認・暫定」。全有効出走馬の値を確認できるまで「直前確認済み」にはしない。
- 大幅増・減や増減なしだけで好不調を断定しない。成長期、休養、前走体重、当日の見た目・近走を合わせて参考評価する。+18kgでも東京10Rの①は3着、増減0でも京都11Rの⑪は11着。
- 現行モデルに学習・検証済みの馬体重係数はない。参考評価を必ず掲載するが、確率の加減点を捏造しない。「参考に使用／確率補正には未使用」を別表示。v49据置。
- 確率へ組み込む段階では、当時の発表時刻・履歴可用性を保ち、2023訓練・2024選択と既に見た2025/2026の回顧評価を分離。今日の当たり外れで閾値・係数・混合率を合わせない。

## 実装

`scripts/preoff_body_weight.py` は当日証拠の検証・参考比較・表表示。`recalculate_weekend_riders.py` はnetkeiba出馬表の現在Weight列を接続し、`report_full_weekend_riders.py` は全頭参照欄と未確認状態を表示する。

新しい直前スナップショットの作成例：

```sh
python scripts/apply_preoff_body_weights.py \
  --prediction <保存予測.json> --observations <発走前馬体重観測.json> \
  --date 2026-11-01 --output <新規直前予測.json> --final-reference
```

`--final-reference` は選択した日付の対象レース全頭の証拠が揃い、実行時点が各発走前の場合だけ成功。レース単位で更新する場合は、その1レースを含む入力JSONを使用する。既存出力の上書きを拒否し、親予測と観測のハッシュを保存。過去の本命・買い目・確率は書き換えない。

観測JSONは `{"races":[{"date":"2026-11-01","race":"東京11R","runners":[...]}]}`。各runnerには `number,name,body_weight_kg,change_kg,first_start,basis="announced_preoff",observed_at,source_url,source_sha256,hash_basis` を持たせる。`hash_basis` は `http_bytes` または `observed_text_export`。未検証のサンプル数値は用意しない。

`history` を付ける場合は当該馬の同一の根拠付きプロフィールURLと、過去レース・実観測時刻・体重・出典URL/SHAを必須とする。`last_off_at` は確認できた場合だけ指定。欠測の通常体重や休養日数を推測しない。

## 検証

発走後・翌日・未来時刻・結果画面・斤量の混入・馬番馬名違い・重複・履歴の別馬混入を拒否する単体テストをCIで実施。保存済み全46R・599頭の再実行で、従来の全モデル出力が不変であることを照合する。基礎モデルの精度改善や馬体重補正の学習完了を意味しない。
